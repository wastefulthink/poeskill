**正文**

```
先说结论：https://github.com/POESKILL_GITHUB_USER/poeskill

一句话：给 Claude Code / Codex / Cline / WorkBuddy 等任何支持 skills 目录的
Agent 装上 32 个斜杠命令，让它在你说"我的方案没问题"时，先给你找出反例，
而不是回你"确实没问题"。

为什么做
--------
用 AI 久了你会发现一个很贵的问题：它几乎不反驳你。不是它坏，是它的对齐
数据奖励顺从。你问"这方案靠谱吗"，它说"靠谱"，于是你带着 10 个"靠谱"
做了一次自己都信以为真的坏决策。这玩意儿有个名字，叫 sycophancy（谄媚）。

修法在权重层很难，但在技能层可控：给 Agent 明确的程序，让它"有建设性地
反驳"。这就是这个项目做的事。

里面有什么
--------
- 32 个 Skill：/poe-verify（带反例压力测试+信源 A–D 分级）、/poe-diagnosis
  （商业模式问诊，咨询+体检双模式）、/poe-deconstruct（拆解"生态位""护城河"
  这类黑话）、/poe-good-question（把模糊需求改写成可推理的问题）、
  /poe-goal（把愿望变成可验收的交付物）、/poe-action（用阿德勒心理学找
  拖延背后的隐藏目标）……
- 305 条"能量库"：从 25 位思想家（休谟、哈耶克、米塞斯、波普尔、费曼、
  卡尼曼、塔勒布、德鲁克、波特、熊彼特、香农、图灵、凯恩斯、索罗斯……）
  提炼，每条都带原文出处（链接+标题+年份）。宁可 305 条全可溯源，不要
  3000 条二手转述。
- 一键安装：./install.sh 自动识别 Claude Code/Codex/Cline/Kiro/Qwen
  Code/WorkBuddy 的 skills 目录，--dry-run 可以先预览。

关于"原创性"的交代
--------
全部内容从零独立撰写：32 个 Skill、知识库、安装器、CI 都是新的。MIT 协议。
无遥测、无注册、无隐藏社群漏斗——你装完不会有任何"回传"。

想请你拍砖的点
--------
1. 305 条知识库对本地小模型（7B）是负担还是资产？（每条都有出处，但也是
   context token）
2. Skill 层的程序化反驳，能多大程度压过模型底层的谄媚？我觉得能显著改善，
   但想听反例。
3. 中文场景里你最想要哪个 Skill？目前内容创作管线的工具最多，商业诊断次之。

star 到 100 就开始做英文版知识库翻译（305 条全量），这是 repo 里写死的
roadmap。
```
